# add-scim-provisioning

## Why

Сейчас пользователи создаются только CLI-командой, а деактивация в Okta до сервиса не доходит вовсе — SAML-вход не сообщает об отключении сотрудника, и его сессии живут до истечения. Архитектурное решение прямо требует SCIM: «Отключение пользователя в Okta должно доходить до общей подсистемы». Референс — рабочий SCIM в GSH (Scimitar): маппинг атрибутов, мягкая деактивация с уничтожением сессий, Bearer-токен.

## What Changes

- Минимальный SCIM 2.0-сервер под клиента Okta: `GET/POST /scim/v2/Users`, `GET/PUT/PATCH/DELETE /scim/v2/Users/{id}`, discovery-эндпоинты `ServiceProviderConfig`, `ResourceTypes`, `Schemas`; фильтр `userName eq "..."` / `externalId eq "..."` (Okta проверяет существование перед созданием), пагинация `startIndex`/`count`.
- Маппинг атрибутов (по GSH): `userName → email`, `displayName → name`, `active → active`; `externalId` (стабильный ID пользователя в Okta) сохраняется как внешняя идентичность `okta-scim` — SAML-вход при совпадении email получает уже подготовленную привязку.
- Деактивация (`active=false` через PUT/PATCH или DELETE) — мягкая: пользователь помечается неактивным и **все его сессии уничтожаются немедленно** (не дожидаясь TTL-кеша); реактивация поддерживается. Физического удаления нет.
- Аутентификация SCIM-клиента: статический Bearer-токен из конфигурации (`SCIM_TOKEN`), сравнение за константное время; без токена в конфигурации SCIM-маршруты не монтируются. Провизионные изменения логируются структурированно (без значений токена).
- `session.Manager` получает операцию уничтожения всех сессий пользователя (по существующему per-user индексу).

Не входит: SCIM Groups (роли назначаются в самом сервисе — единое управление доступом), дефолтная роль при создании (в отличие от GSH: роли принадлежат приложениям, «роль по умолчанию» здесь не определена), несколько SCIM-клиентов/токенов, менеджмент токенов в БД.

## Capabilities

### New Capabilities

- `scim-provisioning`: SCIM 2.0-провижининг пользователей из Okta — создание, обновление профиля, деактивация с отзывом сессий, discovery, аутентификация клиента.

### Modified Capabilities

- `web-sessions`: добавляется требование немедленного уничтожения всех сессий пользователя при его деактивации через провижининг.

## Impact

- Новый пакет `internal/scim` (протокол, хендлеры, фильтр); новые методы `internal/postgres` (создание/обновление пользователя, поиск по email без фильтра активности) и `internal/session` (DestroyAllForUser).
- Конфигурация: `SCIM_TOKEN` (опциональный в development — SCIM выключен без него; обязателен? — нет, SCIM опционален и в production: сервис может жить до подключения Okta).
- Новых внешних зависимостей нет — SCIM-подмножество реализуется стандартной библиотекой.
