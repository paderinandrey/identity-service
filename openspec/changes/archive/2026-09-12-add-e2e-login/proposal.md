# add-e2e-login

## Why

Playwright-тесты фронтов GSH/DFM аутентифицируются нашей cookie — другого auth-состояния у фронта нет. Прогонять каждый тест через форму IdP медленно и флаки; нужен программный способ получить сессию для тестового пользователя (storageState-паттерн Playwright). Полный SSO-флоу остаётся покрыт отдельным smoke-тестом через IdP.

## What Changes

- Endpoint `POST /internal/e2e/login` (тело: `{"email": "..."}`): аутентификация Bearer-токеном `E2E_LOGIN_TOKEN` (по образцу SCIM: constant-time сравнение, минимум 32 символа, без токена в окружении маршрут не монтируется), создаёт обычную сессию для существующего активного пользователя и отвечает штатным Set-Cookie.
- Сессия ничем не отличается от SAML-входа (ротация, лимиты, idle/lifetime), но `last_sign_in_at` не трогает и в `sign_ins_total` не попадает — тестовые входы не искажают ни аналитику, ни метрики.
- Неизвестный или неактивный пользователь → 404/401 без создания сессии.
- Токен MUST NOT задаваться в production (проверка конфигурации: `APP_ENV=production` + заданный `E2E_LOGIN_TOKEN` — ошибка старта).
- README: раздел для команд фронтов — пример global-setup Playwright, нюанс домена cookie, рекомендация одного smoke-теста через IdP на RelayState-флоу.

Не входит: управление тестовыми пользователями (уже есть SCIM/CLI), UI-автоматизация IdP.

## Capabilities

### New Capabilities

- `e2e-login`: программная выдача сессии для автотестов по машинному токену, недоступная в production.

### Modified Capabilities

Нет.

## Impact

- Небольшой пакет/хендлер рядом с session (или в `internal/session`), конфигурация `E2E_LOGIN_TOKEN`, wiring в main вне session-middleware зоны монтирования? (нет — ему нужен scs-контекст: монтируется как /auth/* внутри session middleware, но аутентифицируется токеном). README.
- Новых зависимостей нет.
