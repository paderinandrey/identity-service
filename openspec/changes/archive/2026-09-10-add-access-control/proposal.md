# add-access-control

## Why

Сервис аутентифицирует пользователей, но пока ничего не знает о их правах — а именно единое управление доступом (роли, permissions, назначения) является его ключевой ответственностью по архитектурному решению от 2026-09-09. GSH и DFM ждут от входного контура готовый контекст доступа, чтобы оставить у себя только доменные проверки через ActionPolicy.

## What Changes

- Схема PostgreSQL по архитектурному решению: `applications`, `roles`, `permissions`, `role_permissions`, `user_roles`. Роли принадлежат приложениям (например, `dfm/engineer`, `gsh/sourcing_manager`); у пользователя может быть несколько ролей в разных приложениях.
- Журнал изменений доступа (`access_audit_log`): кто, кому, какое действие (назначение/снятие роли, изменение состава роли), результат и время. Записывается в той же транзакции, что и само изменение.
- Домен `internal/access`: вычисление эффективных прав пользователя (объединение permissions по всем его ролям), кеш с конфигурируемой задержкой отзыва — изменение состава роли или назначений доходит до всех затронутых пользователей не позднее этой задержки.
- Внутренняя проверка сессии дополняется контекстом доступа: endpoint validate отдаёт эффективные права заголовком `X-Identity-Permissions` (формат `app:permission`, через запятую). Это промежуточный формат до выбора подписанного внутреннего токена (открытый вопрос архитектуры).
- CLI для bootstrap до появления GraphQL API: `grant-role` / `revoke-role` (пользователю), `seed-access` (создание приложения/роли/permissions из декларативного YAML/JSON-файла). Управляющие операции пишут в журнал с актором `cli`.

Не входит: GraphQL API управления доступом (отдельное изменение, введёт gqlgen), UI, события изменений в RabbitMQ, перенос существующих назначений из GSH.

## Capabilities

### New Capabilities

- `access-control`: модель доступа — приложения, роли, permissions, назначения, журнал изменений, вычисление эффективных прав.

### Modified Capabilities

- `web-sessions`: внутренняя проверка сессии дополнительно возвращает эффективные права пользователя в заголовке ответа.

## Impact

- Новые пакеты: `internal/access` (домен + операции), реализация хранения в `internal/postgres`; новые goose-миграции.
- Расширяется `internal/session` (заголовок прав в validate) и CLI в `cmd/identity-service`.
- Новая конфигурация: `PERMISSIONS_CACHE_TTL` (задержка отзыва прав, default 60s — согласована с `USER_REVOCATION_DELAY`).
- Новых внешних зависимостей нет (pgx/goose уже введены; YAML для seed — `gopkg.in/yaml.v3` или JSON стандартной библиотекой — решение в design).
