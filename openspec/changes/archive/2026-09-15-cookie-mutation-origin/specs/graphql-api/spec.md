# graphql-api — delta

## MODIFIED Requirements

### Requirement: Мутации назначений с авторизацией
Мутации `grantRole` и `revokeRole` SHALL выполняться только вызывающими с permission `identity:access.manage`; остальные SHALL получать ошибку `FORBIDDEN` без изменения данных. Мутации, аутентифицированные cookie-сессией, SHALL проверять заголовок `Origin` до исполнения: отсутствующий Origin допускается, непустой SHALL входить в доверенный список (базовый URL сервиса и frontend), иначе — ошибка `FORBIDDEN` без изменения данных. Запросы на чтение Origin MUST NOT требовать. Успешная мутация SHALL быть идемпотентной и записываться в журнал изменений доступа с актором — вызывающим пользователем.

#### Scenario: Назначение с правом управления
- **WHEN** пользователь с `identity:access.manage` выполняет `grantRole`
- **THEN** назначение создаётся, журнал содержит запись с его глобальным ID как актором

#### Scenario: Назначение без права управления
- **WHEN** аутентифицированный пользователь без `identity:access.manage` выполняет `grantRole`
- **THEN** ответ содержит ошибку `FORBIDDEN`, назначение не создаётся, журнал не пополняется

#### Scenario: Несуществующая роль
- **WHEN** `grantRole` вызывается с неизвестной ролью
- **THEN** возвращается понятная ошибка, данные не меняются

#### Scenario: Мутация с чужим Origin
- **WHEN** мутация приходит с действующей сессией администратора и заголовком `Origin`, не входящим в доверенный список
- **THEN** ответ содержит ошибку `FORBIDDEN`, назначение не создаётся, журнал не пополняется; та же мутация с доверенным Origin или без Origin выполняется
