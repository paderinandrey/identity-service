## MODIFIED Requirements

### Requirement: Запуск с конфигурацией из окружения
Сервис SHALL читать конфигурацию из переменных окружения при старте: публичный адрес прослушивания HTTP, внутренний адрес прослушивания HTTP, имя окружения (development/staging/production), уровень логирования, строки подключения PostgreSQL и Redis, базовый URL сервиса, URL метаданных IdP, секрет подписи RelayState, базовый URL frontend и параметры сессий (имя cookie, idle-timeout, абсолютный срок, лимит одновременных сессий). Для отсутствующих переменных SHALL применяться безопасные значения по умолчанию, пригодные для локальной разработки; вне development параметры подключений, URL и секреты SHALL быть обязательными — их отсутствие является ошибкой старта. Пустое значение текстовой переменной SHALL трактоваться как её отсутствие; пустое значение числовой, булевой переменной или длительности SHALL быть недопустимым значением. Вне development секрет подписи RelayState SHALL быть не короче 32 символов и не совпадать с dev-значением по умолчанию. При запуске внутри Kubernetes имя окружения SHALL быть задано явно: его отсутствие является ошибкой старта, а не development по умолчанию. Публичный и внутренний адреса MUST различаться; совпадение SHALL быть ошибкой старта. Бинарник SHALL печатать перечень переменных с описаниями и значениями по умолчанию по команде `env`, не требуя заданной конфигурации.

#### Scenario: Старт с валидной конфигурацией
- **WHEN** процесс запускается с корректными переменными окружения
- **THEN** сервис начинает слушать публичный и внутренний адреса и пишет в лог факт старта с именем окружения и обоими адресами

#### Scenario: Старт с невалидной конфигурацией
- **WHEN** переменная окружения содержит недопустимое значение (например, нераспознанный уровень логирования)
- **THEN** процесс завершается с ненулевым кодом выхода и понятным сообщением об ошибке, не начиная принимать трафик

#### Scenario: Пустое значение переменной
- **WHEN** текстовая переменная (например, `SESSION_COOKIE_NAME`) задана пустой строкой
- **THEN** применяется её значение по умолчанию, как если бы переменная отсутствовала

#### Scenario: Пустое значение типизированной переменной
- **WHEN** переменная-длительность, число или булево значение (например, `SHUTDOWN_TIMEOUT`) задана пустой строкой
- **THEN** процесс завершается с ненулевым кодом выхода и сообщением, называющим переменную

#### Scenario: Отсутствие обязательных параметров вне development
- **WHEN** процесс запускается с `APP_ENV=production` без строки подключения PostgreSQL, Redis или секрета RelayState
- **THEN** процесс завершается с ненулевым кодом выхода и сообщением, какие переменные отсутствуют

#### Scenario: Слабый секрет RelayState вне development
- **WHEN** процесс запускается с `APP_ENV=staging` и секретом RelayState короче 32 символов или равным dev-значению по умолчанию
- **THEN** процесс завершается с ошибкой конфигурации

#### Scenario: APP_ENV не задан в Kubernetes
- **WHEN** процесс запускается в поде Kubernetes без переменной `APP_ENV`
- **THEN** процесс завершается с ошибкой конфигурации, не переходя в development

#### Scenario: Публичный и внутренний адреса совпадают
- **WHEN** внутренний адрес прослушивания равен публичному
- **THEN** процесс завершается с ненулевым кодом выхода и сообщением, что адреса зон должны различаться

#### Scenario: Справка по переменным
- **WHEN** бинарник запускается с командой `env` без единой заданной переменной
- **THEN** он печатает все переменные конфигурации с описаниями и значениями по умолчанию и завершается с нулевым кодом
