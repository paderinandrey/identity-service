# assignments-import

## Why

Перенос доступа из GSH ([[2026-09-18-gsh-integration]], стадия A) требует
завести в identity-service назначения ролей для всех существующих
пользователей GSH разом: таблица `users_roles` там содержит сотни строк,
а единственный способ назначить роль сейчас — `grant-role` по одному
email за запуск. Ручной цикл из сотен вызовов не воспроизводим и не
оставляет отчёта, а API управления назначениями пока нет (спека
`access-control`, «Bootstrap-управление через CLI»). Нужен файл-импорт:
идемпотентный, перезапускаемый и с отчётом, чтобы cutover можно было
прогнать сначала на стенде, затем на staging, затем повторить без
страха задвоить или частично применить.

## What Changes

- Новая CLI-команда `import-assignments --file <yaml> [--dry-run]`:
  список записей «пользователь → роли `app/role`», пользователь по `id`
  (глобальный UUID) или по `email` — как в `grant-role`, это bootstrap
  через доверенный CLI, а не рантайм-линковка.
- Файл валидируется целиком до первой записи в базу: синтаксис ссылок на
  роли, ровно один из `id`/`email`, непустые роли, дубликаты записей.
- Роли одного пользователя назначаются в одной транзакции: неизвестная
  роль или пользователь откатывает запись целиком, остальные записи
  применяются; уже назначенные роли — no-op без записи в журнал (как в
  `grant-role`). Завершение с ненулевым кодом, если хотя бы одна запись
  не применилась; повторный запуск после исправления файла безопасен.
- Отчёт по каждой записи (назначено / уже было / ошибка) и итог; журнал
  доступа получает записи с актором `cli`, как и остальные CLI-операции.
- `seed-access` не меняется: он по-прежнему MUST NOT трогать назначения.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `access-control`: требование «Bootstrap-управление через CLI»
  дополняется командой импорта назначений с её гарантиями
  (идемпотентность, атомарность записи, dry-run, отчёт, код выхода).

## Impact

- `internal/access`: типы файла импорта и их валидация (юнит-тесты).
- `internal/postgres`: `GrantRoles` — назначение набора ролей одному
  пользователю в одной транзакции (интеграционные тесты, включая откат
  при неизвестной роли).
- `cmd/identity-service/main.go`: подкоманда, разбор файла, отчёт.
- README: раздел «Access control» — формат файла и порядок cutover.
- Совместимость: только добавление; миграций нет.
