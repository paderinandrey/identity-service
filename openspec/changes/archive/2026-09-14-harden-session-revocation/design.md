# harden-session-revocation — Design

## Context

Сессии — scs v2.9 поверх goredisstore; `Manager.Start` кладёт `user_id`,
индекс `user_sessions:<uid>` (zset токенов) служит для лимита и для
`DestroyAllForUser`. scs при `IdleTimeout > 0` помечает загруженную сессию
`Modified` и коммитит её в конце запроса — это и воскрешает удалённую.
Проверка пользователя (`currentUser` в session, `authMiddleware` в graphql)
идёт через `UserCache` с задержкой `USER_REVOCATION_DELAY` (60s). SCIM
`deactivate`: `SetActive(false)` в транзакции с событием outbox, затем
`DestroyAllForUser`, ошибка которого только логируется.

## Decisions

1. **Поколение живёт в PostgreSQL** (`users.session_epoch bigint NOT NULL
   DEFAULT 0`, миграция `00008`, аддитивная) и попадает в `identity.User`.
   Это единственный источник правды об отзыве; Redis его зеркалит.
   Альтернатива «только Redis INCR» отвергнута: отказ Redis в момент
   деактивации оставил бы отзыв незаписанным нигде — ровно F3.

2. **Сессия несёт поколение.** `Manager.Start(ctx, userID, epoch)` кладёт
   `user_id` и `epoch` (значение — `user.SessionEpoch` на момент входа;
   SAML и e2e-login передают его из найденного пользователя). Сессии без
   поля (созданные до этого change) читаются как поколение 0 — они
   валидны до первого отзыва у пользователя, что совпадает со старым
   поведением и не требует массового разлогина при деплое.

3. **Деактивация поднимает поколение в той же транзакции.** `SetActive`
   при переходе в `false` делает `session_epoch = session_epoch + 1` вместе
   с `active = false`, `version + 1` и событием outbox, и возвращает
   обновлённого пользователя. Переход в `true` поколение не меняет. Так
   отзыв атомарен с деактивацией, а реактивация никогда не оживляет
   старые сессии.

4. **Redis-ограждение в обёртке хранилища сессий.** `session` оборачивает
   goredisstore: `FindCtx` декодирует данные (`scs.GobCodec`, тот же
   кодек, что использует scs) и сравнивает `epoch` сессии с ключом
   `user_epoch:<uid>`; при расхождении сессия считается не найденной (и
   удаляется). `CommitCtx` делает ту же проверку и *не пишет* устаревшую
   сессию. Проверка в хранилище, а не в хендлерах — потому что
   пересохранение делает сам scs, ниже любого нашего middleware; только
   здесь можно перехватить коммит запроса в полёте. Ошибка Redis в обёртке
   уходит в scs `ErrorFunc` → 503, как и сейчас.

5. **`DestroyAllForUser(ctx, userID, epoch)` сначала ставит ограждение**
   (`SET user_epoch:<uid> <epoch>`), потом удаляет сессии по индексу.
   Порядок важен: с ограждением любая не удалённая сессия всё равно мертва;
   удаление ключей — гигиена, а не гарантия. `Start` тоже пишет ключ
   (`SET` тем же значением, идемпотентно), чтобы ограждение существовало и
   без деактиваций.

6. **Второй рубеж — поколение из PostgreSQL в проверке пользователя.**
   `currentUser` и graphql `authMiddleware` сравнивают поколение сессии с
   `user.SessionEpoch` из `UserCache`. Это ловит случай, когда `SET`
   ограждения в Redis не удался: отставание ограничено задержкой отзыва,
   как и для признака `active`. `UserSource` получает поколение через уже
   существующий `FindByID`; новых методов не нужно.

7. **Отказ Redis при деактивации — не откат и не 500.** К этому моменту
   отзыв уже долговечен (п. 3). `deactivate` логирует ошибку, увеличивает
   метрику `session_revocation_errors_total` и отвечает провижинингу
   успехом: пользователь деактивирован, и это правда. Пока Redis лежит,
   проверка сессий отвечает 503 (fail-close, уже так); после восстановления
   старые сессии отклоняются по п. 6 не позднее задержки отзыва. Возвращать
   500 и ждать повторного PATCH от Okta нельзя: при повторе пользователь
   уже неактивен, и ветка удаления не выполнится (замечание Codex).

8. **`EffectivePermissions` фильтрует неактивных** (`JOIN users … AND
   active`) — спека `access-control` это обещает, метод не делал. HTTP-пути
   и так проверяли `active` отдельно; теперь контракт метода честный.

9. **По итогам ревью Codex (PR #2): ограждение монотонно, коммит
   атомарен.** Безусловный `SET` при входе мог откатить ограждение на
   поколение, прочитанное из базы до параллельной деактивации, а проверка
   и запись в `CommitCtx` оставляли окно, в которое отзыв успевал
   проскочить. Оба места переведены на Lua-скрипты: `raiseFence` меняет
   ключ только вверх и возвращает итог (вход, увидевший ограждение выше
   своего поколения, получает `ErrUserRevoked` и отвечает 401),
   `commitFenced` сравнивает и пишет одной командой.

## Risks / Trade-offs

- Один дополнительный `GET` в Redis на каждую загрузку сессии (validate —
  горячий путь). Ключи `user_epoch` без TTL — их столько, сколько
  пользователей когда-либо входили; объём пренебрежим.
- Двойное декодирование сессии (обёртка + scs). Сессия — два поля,
  стоимость незаметна на фоне сетевого вызова.
- Существующие сессии без поколения остаются валидны до первого отзыва —
  осознанно, чтобы деплой не разлогинивал всех.
