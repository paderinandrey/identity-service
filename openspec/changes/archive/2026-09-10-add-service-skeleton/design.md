# add-service-skeleton — Design

## Context

Репозиторий пуст (кроме `openspec/` и `.claude/`). Архитектурное решение GSH/DFM от 2026-09-09 зафиксировало язык (Go) и общую топологию, но большая часть стека сознательно не выбрана. Скелет должен дать рабочую основу, не предрешая эти выборы. Мотивация — см. proposal.md, «Why»; требования — specs/service-runtime/spec.md.

## Goals / Non-Goals

**Goals**
- Собираемый и тестируемый сервис с минимальным набором зависимостей.
- Точки расширения, куда позже лягут SAML, сессии, GraphQL и БД, без перестройки каркаса.
- Одинаковый запуск локально (mise) и в контейнере (Dockerfile).

**Non-Goals**
- Никакой бизнес-логики: ни аутентификации, ни хранилищ, ни API кроме health.
- Не выбираем сторонние библиотеки (роутер, GraphQL, SAML, миграции) — это предмет отдельного explore/решения.
- Не настраиваем CI-платформу (только локальные таски, которые CI потом переиспользует).

## Decisions

1. **Только стандартная библиотека Go.** `http.ServeMux` (Go ≥ 1.22 поддерживает методы и шаблоны путей), `log/slog` для JSON-логов, `os/signal.NotifyContext` для shutdown. Альтернатива — chi/echo: отклонена, роутер легко добавить позже, а лишняя зависимость в скелете сузила бы будущий выбор GraphQL-стека.
2. **Структура каталогов** — стандартная для Go-сервисов: `cmd/identity-service/main.go` (сборка зависимостей и запуск), `internal/config` (чтение/валидация env), `internal/httpserver` (mux, health-хендлеры, graceful shutdown). Альтернатива — плоский `main.go`: отклонена, сервис заведомо вырастет.
3. **Конфигурация — чистые переменные окружения** (`PORT`/`LISTEN_ADDR`, `APP_ENV`, `LOG_LEVEL`, `SHUTDOWN_TIMEOUT`), парсинг руками в `internal/config` без viper/envconfig. Значения по умолчанию безопасны для локальной разработки; невалидные значения — ошибка старта (fail fast).
4. **Readiness через атомарный флаг**: `/readyz` читает `atomic.Bool`, который сбрасывается при получении сигнала остановки до вызова `server.Shutdown`. Это даёт Kubernetes окно на вывод пода из балансировки.
5. **Версия Go пинится в `mise.toml`**: Go 1.27 (актуальная стабильная линия на 2026-09; при реализации брать последний патч). Там же таски `build`, `test`, `lint`, `run`, `up` (docker-compose). Альтернатива — Makefile: mise уже используется в окружении разработчика и управляет и версией toolchain, и тасками.
6. **Dockerfile multi-stage**: сборка на официальном образе Go, рантайм — distroless/static или alpine, бинарник статический (`CGO_ENABLED=0`). Контейнер слушает `$PORT`, завершается по SIGTERM (важно: процесс — PID 1, сигналы обрабатываем сами).
7. **docker-compose с PostgreSQL 18 и Redis 8.10** (актуальные линии на 2026-09, зафиксированы в исследовании стека в архитектурной заметке) — только инфраструктура для будущих изменений; приложение к ним пока не подключается, healthcheck-и контейнеров настроены заранее.
8. **golangci-lint** с умеренным набором линтеров в `.golangci.yml` — единственная dev-зависимость (ставится через mise, в `go.mod` не попадает).

## Risks / Trade-offs

- [Стандартный mux окажется недостаточным при добавлении GraphQL/middleware] → Каркас изолирует роутинг в `internal/httpserver`; замена роутера — локальное изменение.
- [Пин версии Go устареет] → mise обновляет версию одной строкой; линтер и Dockerfile берут версию из одного места (документируется в README).
- [docker-compose-контейнеры без потребителей «протухнут» (версии, настройки)] → Явно помечены в README как заготовка; параметры уточняются в изменении, которое их подключит.

## Migration Plan

Развёртывания ещё нет — скелет создаёт первую версию. Rollback = откат коммита. Kubernetes-манифесты не входят в это изменение.
