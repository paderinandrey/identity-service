# graphql-limits

## Why

Обзоры 14.09 (Codex, Antigravity, Cursor) сходятся на четырёх пробелах
GraphQL/HTTP, ни один из которых не воспроизведён как инцидент, но все —
открытые двери для аутентифицированного, но недобросовестного или просто
неудачного запроса:

1. **Тело запроса не ограничено**: SAML и SCIM режут тело, `/graphql` —
   нет; POST-транспорт gqlgen читает всё, что прислали.
2. **Нет бюджета сложности**: `users` ограничен 200 элементами, но один
   запрос с десятком алиасов `users` и вложенными `roles` — это тысячи
   строк и сотни SQL-запросов.
3. **N+1 на `User.roles`**: для каждого пользователя страницы отдельный
   запрос назначений — до 200 запросов на один список.
4. **Нет пагинации**: каталог больше 200 пользователей недостижим через
   API вовсе; HTTP-сервер имеет `ReadHeaderTimeout`, но не имеет
   `ReadTimeout`/`WriteTimeout`/`IdleTimeout`.

## What Changes

- Тело `/graphql` ограничено 1 MiB — тем же механизмом, что SAML и SCIM.
- Бюджет сложности запроса (gqlgen `FixedComplexityLimit`) с учётом
  размера списков: стоимость `users` умножается на запрошенный размер
  страницы, `accessAuditLog` — на `limit`. Превышение — ошибка до
  исполнения, без обращений к базе.
- `users` становится курсорной страницей: `first` (по умолчанию 50, не
  больше 200) и `after`; ответ — `UserConnection { nodes, pageInfo }`.
  Keyset по `(name, email, id)`, курсор непрозрачный. Ломающее изменение
  схемы; потребителей у поля пока нет (стенд и стаб его не используют).
- Назначения ролей для страницы пользователей загружаются одной выборкой
  и раздаются `User.roles` из request-scoped кеша; одиночные запросы
  (`user`, `_entities`) работают как прежде.
- HTTP-сервер получает `ReadTimeout`, `WriteTimeout`, `IdleTimeout`.

## Capabilities

### Modified Capabilities

- `graphql-api`: endpoint ограничивает размер тела и сложность запроса;
  справочник пользователей постраничный; список с ролями обходится одной
  выборкой назначений.

## Impact

`internal/graphql` (схема, сгенерированный код, резолверы, middleware),
`internal/postgres` (`SearchUsers` с keyset, `AssignmentsForUsers`),
`internal/httpserver` (таймауты), тесты, README и Yaak-запрос `users`
(на стороне владельца).
