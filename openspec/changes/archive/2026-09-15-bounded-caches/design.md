# bounded-caches — Design

## Context

`UserCache.lookup` и `PermissionsCache.EffectivePermissions` — копии
друг друга: lock → map read → unlock → (miss) store call → lock → map
write. Метрика — только hit/miss. Тесты используют инжектируемое поле
`now` для проверки TTL.

## Decisions

1. **Generic-кеш как отдельный пакет.** `cache.Cache[V]` с `New[V](capacity,
   ttl, load func(ctx, key string) (V, error))` и `Get(ctx, key) (V,
   error)`. Две одинаковые реализации — достаточная причина для
   абстракции: она убирает дублирование и даёт одно место для
   вытеснения и объединения загрузок. Домен (`identity`, `access`) от
   пакета зависит как от утилиты; пакет от домена — нет.

2. **LRU на `container/list` + `map`**, не `golang-lru`: вся логика — 40
   строк, а библиотека потянула бы foundational-зависимость ради них.
   Порядок «недавно использованные» обновляется при hit; при
   переполнении удаляется хвост. Протухшая запись, найденная при чтении,
   удаляется на месте, чтобы не занимать ёмкость.

3. **Singleflight на промахах** через `golang.org/x/sync/singleflight` (уже в
   графе модулей). Одновременные `Get` одного ключа ждут одну загрузку и
   получают её результат; ошибка загрузки не кешируется и достаётся всем
   ожидающим.

4. **Отрицательные записи остаются.** Loader пользователя переводит
   `ErrUserNotFound` в `nil`-значение, которое кешируется, как и сейчас:
   неизвестные id не должны бить в базу.

5. **Ёмкость общая настройка** `CACHE_MAX_ENTRIES` (default 10 000) для
   обоих кешей: разные пределы для двух кешей одинаковой природы — лишняя
   ручка.

6. **Метрики.** `cache_entries{cache}` (gauge, обновляется после каждой
   записи/вытеснения) и `cache_evictions_total{cache}`. Интерфейс
   `cache.Metrics{Observe(hit), SizeSet(n), Evicted()}`; адаптер
   observability реализует его для именованного кеша.

## Risks / Trade-offs

- LRU под одним мьютексом — как и сейчас; validate-путь короткий, 
  contention незаметен при наших RPS.
- Singleflight держит ожидающих на время одной загрузки (мс); при
  недоступной базе все ждущие получают одну и ту же ошибку — это то же
  fail-close, что и раньше, только с одним запросом вместо N.
