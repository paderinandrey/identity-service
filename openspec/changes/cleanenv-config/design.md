# cleanenv-config — Design

## Context

`config.Load` читает 25 переменных вручную, для каждой свой разбор.
Спека `service-runtime` требует: значения по умолчанию для development,
обязательность подключений, URL и секретов вне development, явный
`APP_ENV` в Kubernetes, ошибку старта при недопустимом значении,
различие публичного и внутреннего адресов. Тесты `internal/config`
покрывают эти правила и используют пустую строку как «переменная не
задана». Мотивация в proposal.md.

## Goals / Non-Goals

**Goals:**
- Одно описание переменной в одном месте: имя, значение по умолчанию,
  текст справки в тегах поля.
- Все текущие правила валидации и тексты ошибок сохраняются.
- Справка по переменным доступна из бинарника.

**Non-Goals:**
- Чтение `.env` или файлов конфигурации: cleanenv умеет, но его режим
  `.env` перекрывает переменные процесса, что для сервиса в Kubernetes
  неприемлемо. Источник остаётся один: окружение процесса.
- Изменение имён переменных, значений по умолчанию или чарта.
- Замена валидации на теги `env-required`: обязательность зависит от
  `APP_ENV`, тегами это не выражается.

## Decisions

1. **Библиотека: cleanenv v1.5.0, по запросу владельца.** Что даёт:
   теги с описанием, `GetDescription` для справки, поддержка
   `time.Duration` и `encoding.TextUnmarshaler` (для `slog.Level`).
   Компромисс, принятый осознанно: последний релиз июль 2023; тянет
   парсеры TOML, EDN и godotenv, которые сервис не использует;
   функциональность, которую мы берём, покрывается и более узкой
   `caarlos0/env`. Если сопровождение cleanenv остановится, замена на
   `caarlos0/env` это переименование тегов в одной структуре, модель
   не меняется.

2. **Defaults в тегах, константы `Default*` остаются.** Константы
   нужны тестам и README как имена, теги нужны библиотеке.
   `TestDefaultsMatchTags` загружает конфигурацию без переменных и
   сравнивает с константами, чтобы дубликаты не разошлись.

3. **Пустая строка.** cleanenv применяет `env-default` только когда
   переменной нет; заданная пустая строка передаётся в разбор. Для
   текстовых полей после `ReadEnv` выполняется `applyTextDefaults`:
   пустое поле с тегом `env-default` получает значение тега, как
   раньше. Для чисел, длительностей и булевых пустая строка становится
   ошибкой разбора с именем переменной, как любое другое непарсимое
   значение. Это единственное изменение наблюдаемого поведения; оно
   безопаснее прежнего: пустая `SHUTDOWN_TIMEOUT` теперь не превратится
   молча в 10 секунд.

4. **Подключения, URL и секрет без `env-default`.** Их отсутствие вне
   development должно быть ошибкой; значение по умолчанию в теге это
   скрыло бы. Development-значения по-прежнему подставляет
   `applyDevelopmentDefaults` после проверки окружения.

5. **Валидация в `validate` после `ReadEnv`**, тем же списком правил и
   с теми же текстами. Проверка «APP_ENV в Kubernetes» смотрит на
   `os.Getenv(APP_ENV)`, а не на поле: пустая или отсутствующая
   переменная одинаково означают, что под её не задал.

6. **Подкоманда `env`** отвечает до `config.Load`: справка нужна как
   раз тогда, когда конфигурация ещё не собрана.

## Risks / Trade-offs

- Развёртывание с пустой типизированной переменной перестанет
  стартовать. В чартах репозитория таких значений нет; сообщение
  называет переменную.
- Три транзитивные зависимости без использования. Проверены `go mod
  verify` и `govulncheck` в CI как остальные.

## Migration Plan

Одна замена файла, без миграций и без изменений чарта. Откат: revert
коммита.
