# relay-lease

## Why

Публикатор outbox нарушает три правила и одно обещание спеки:

1. **Сеть внутри транзакции.** `drainOnce` держит `FOR UPDATE` на пачке
   строк, пока ждёт подтверждений брокера — до 100 × 5 с. AGENTS.md:
   «avoid external network calls inside database transactions».
2. **Нет пути для постоянных отказов.** Неудача увеличивает `attempts`,
   но строка остаётся первой в очереди: одно битое событие останавливает
   всё. Правило «use bounded retries with backoff and classify permanent
   failures» не выполняется.
3. **Порядок между репликами.** Спека `user-events` обещает публикацию
   событий одного пользователя в порядке записи; `SKIP LOCKED` на двух
   репликах (`replicaCount: 2` по умолчанию) этого не гарантирует — каждая
   берёт свою пачку.
4. **Опубликованное хранится вечно**, а неразмеченные очереди
   (`mandatory=false`) принимают событие «в никуда»: брокер подтверждает
   сообщение, которое не попало ни в одну очередь, и оно считается
   доставленным.

Всё отмечено обзорами 14.09 (Codex, Cursor, Antigravity), сверено по коду
в [[2026-09-14-triage-and-plan]].

## What Changes

- **Lease вместо блокировки.** Короткая транзакция помечает пачку строк
  арендой (`lease_until`, `leased_by`) и коммитит; публикация с
  подтверждениями идёт вне транзакции; итог фиксируется второй короткой
  транзакцией. Просроченная аренда возвращает строку в очередь.
- **Порядок на пользователя — head-of-line.** Строка берётся в работу
  только если это самое раннее неопубликованное событие своего
  пользователя. Две реплики никогда не держат события одного
  пользователя одновременно; ordering выполняется строго, без ограничения
  «одна реплика на деплой».
- **Карантин.** После `N` неудачных попыток с экспоненциальным backoff
  строка помечается `quarantined_at` и перестаёт блокировать остальные.
  CLI `requeue-events` возвращает карантинные строки в очередь. Метрика
  `outbox_quarantined`.
- **Неразмеченные события не теряются.** Публикация с `mandatory=true`;
  возврат брокера (нет очереди) — не ошибка и не попытка: событие ждёт
  консьюмера с максимальным backoff, метрика `outbox_unroutable_total`.
  Топология: сервис объявляет только exchange, очереди и bindings —
  ответственность консьюмеров.
- **Retention.** Опубликованные строки старше `OUTBOX_RETENTION`
  (по умолчанию 30 дней) удаляются пачками из цикла relay.
- **Метрики при авариях.** `outbox_pending`, `outbox_quarantined` и
  `outbox_oldest_pending_age_seconds` обновляются каждый цикл, включая
  циклы с недоступным брокером.
- Схема: `user_id`, `lease_until`, `leased_by`, `quarantined_at` в outbox;
  data-миграция заполняет `user_id` из payload существующих строк.

## Capabilities

### Modified Capabilities

- `user-events`: надёжная публикация формулируется через аренду, порядок
  на пользователя между репликами, карантин и неразмеченные события;
  добавляются требования о карантине с восстановлением и о хранении
  опубликованных событий.

## Impact

`internal/events` (relay переписан, интерфейс `Publisher` для тестов),
`internal/postgres/events.go` (`user_id`, requeue), миграции `00009`
(схема) и `00010` (данные), `internal/config` (`OUTBOX_RETENTION`),
`cmd` (`requeue-events`), `internal/observability` (три метрики),
README, тесты relay на настоящих PostgreSQL и RabbitMQ.
