# web-sessions

## Purpose

Серверные браузерные сессии в Redis: единственный держатель состояния аутентификации для всей экосистемы. Браузер хранит только непрозрачный идентификатор в HttpOnly cookie; проверка сессии предоставляется внутренним API для ext-auth входного proxy.

## Requirements

### Requirement: Создание сессии при входе
При успешном SAML-входе сервис SHALL создавать сессию в Redis с непредсказуемым идентификатором и выдавать его в cookie с атрибутами `HttpOnly`, `Secure` (вне development), `SameSite=Lax` и согласованным `Path`. Идентификатор сессии SHALL ротироваться при каждом входе; данные сессии SHALL включать идентификатор пользователя и время создания. Пароли и токены MUST NOT попадать в cookie или localStorage.

#### Scenario: Cookie после входа
- **WHEN** пользователь успешно вошёл через SAML
- **THEN** браузер получает cookie c непрозрачным идентификатором и атрибутами HttpOnly, SameSite=Lax и Secure вне development

#### Scenario: Ротация при повторном входе
- **WHEN** пользователь с действующей сессией снова проходит вход
- **THEN** прежний идентификатор сессии перестаёт действовать, выдаётся новый

### Requirement: Срок жизни сессии
Сессия SHALL истекать по idle-timeout (продлевается активностью) и по абсолютному сроку жизни; оба значения конфигурируются. Истёкшая сессия SHALL считаться недействительной без обращения к другим системам.

#### Scenario: Истечение по бездействию
- **WHEN** с момента последней активности прошло больше idle-timeout
- **THEN** сессия недействительна, запросы с её cookie получают 401

#### Scenario: Абсолютный срок
- **WHEN** с момента создания сессии прошло больше абсолютного срока жизни
- **THEN** сессия недействительна независимо от активности

### Requirement: Завершение сессии
Сервис SHALL по `POST /auth/logout` удалять серверную сессию и сбрасывать cookie. Запрос SHALL приниматься только методом POST; для защиты от CSRF SHALL проверяться заголовок Origin (или Sec-Fetch-Site) на соответствие разрешённым источникам.

#### Scenario: Выход
- **WHEN** аутентифицированный пользователь отправляет `POST /auth/logout` с корректным Origin
- **THEN** серверная сессия удаляется, cookie сбрасывается, повторные запросы с прежним идентификатором получают 401

#### Scenario: Кросс-доменный logout отклоняется
- **WHEN** `POST /auth/logout` приходит с чужим Origin
- **THEN** сервис отвечает отказом и сессию не удаляет

### Requirement: Лимит одновременных сессий
Число одновременных сессий одного пользователя SHALL ограничиваться конфигурируемым значением; вход сверх лимита SHALL вытеснять самые старые сессии пользователя.

#### Scenario: Вытеснение старейшей сессии
- **WHEN** пользователь входит, уже имея максимальное число сессий
- **THEN** новая сессия создаётся, а самая старая перестаёт действовать

### Requirement: Текущий пользователь
Сервис SHALL по `GET /auth/me` возвращать данные пользователя текущей сессии (глобальный ID, email, имя). Без действительной сессии ответ SHALL быть 401.

#### Scenario: Запрос с действующей сессией
- **WHEN** приходит `GET /auth/me` с валидной session cookie
- **THEN** сервис отвечает 200 с глобальным ID, email и именем пользователя

#### Scenario: Запрос без сессии
- **WHEN** приходит `GET /auth/me` без cookie или с недействительной сессией
- **THEN** сервис отвечает 401

### Requirement: Внутренняя проверка сессии
Сервис SHALL предоставлять внутренний HTTP endpoint проверки сессии для ext-auth входного proxy: по cookie из запроса он SHALL возвращать 200 с контекстом пользователя (глобальный ID, email) и его эффективными правами в формате `application:permission` (через запятую) в ответных заголовках либо 401. Недоступность зависимостей MUST NOT приводить к ответу 200 (fail-close). Endpoint MUST NOT быть достижим через публичную маршрутизацию.

#### Scenario: Валидная сессия
- **WHEN** proxy передаёт запрос с cookie действующей сессии активного пользователя
- **THEN** ответ 200 содержит заголовки с глобальным ID, email и эффективными правами пользователя

#### Scenario: Пользователь без назначенных ролей
- **WHEN** у пользователя действующей сессии нет ни одной роли
- **THEN** ответ 200 содержит идентификационные заголовки и пустой заголовок прав

#### Scenario: Недействительная сессия
- **WHEN** cookie отсутствует, сессия истекла или пользователь деактивирован
- **THEN** ответ 401 без контекста пользователя

#### Scenario: Redis недоступен
- **WHEN** хранилище сессий недоступно при проверке
- **THEN** ответ является ошибкой, а не 200; запрос не пропускается как авторизованный

### Requirement: Деактивация пользователя завершает доступ
Проверка сессии SHALL учитывать актуальный признак активности пользователя: сессии деактивированного пользователя SHALL считаться недействительными не позднее конфигурируемой задержки отзыва.

#### Scenario: Сессия деактивированного пользователя
- **WHEN** пользователь деактивирован, а его сессия ещё не истекла
- **THEN** внутренняя проверка сессии и `GET /auth/me` отвечают 401 не позднее задержки отзыва
